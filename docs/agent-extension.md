# Agent 扩展与维护

## 分层
- `team.ts`：内置岗位、报告类型与报告校验。浏览器可使用，不读取密钥。
- `team-config.ts`：项目配置 Schema、默认配置工厂、纯校验函数。
- `team-runtime.ts`：会审输入、调用和报告持久化到内存状态；由 server 统一原子保存。
- `skills.ts`：基础阶段规范与当前启用部门规范合成。
- `agent-customization.tsx`：项目配置编辑；`agent-team.tsx`：岗位展示和调用。

## 自定义
在制作团队中新增岗位，修改名称、输出要求和专业规范。高级 JSON 可修改 id、stages、enabled 和 model。合法阶段沿用状态图；新增岗位不能绕过剧本批准、实际采用参考版本的批准、队列预算或素材审查。并非要求全库齐图：不可或缺主图仅阻断相关媒体生成，建议与可选资产可以文字设计继续。
配置只存于当前作品的 production.agentConfig，具有 version:1。最多 40 个岗位，ID 唯一；至少一个启用。独立会审模型覆盖使用同一语言模型 API 和密钥，不接受任意脚本、接口地址或插件代码。
阶段主执行器仍使用全局语言模型；岗位 model 字段作用于独立会审和自动协作的岗位调用。岗位的 checks/deliverable 会合并入相关工作流阶段的提示词。

## 版本与兼容
旧作品没有配置时使用 17 个默认岗位。保存配置增加 agentConfigRevision；报告同时绑定作品 revision 与配置 revision。旧报告保留，标记过期，并从后续会审上下文排除。配置修改不自动改写剧本或删除素材。
停用岗位不会删除其历史报告；模型返工目标只能引用本次启用岗位。会审失败不写入半成品。

## 扩展方式
新增艺术岗位优先走配置，不在 server 增加 if 分支。新增有副作用的工具应编写单独适配器、显式校验参数，并接入现有确认与队列逻辑。当前并非任意插件执行平台；供应商模块和工作流大接口仍可继续分阶段拆分，避免一次重构破坏已有任务恢复。

## 清理范围
本次移除了主接口中的内联会审实现及重复 assets import，将抽取模块格式化为可审阅代码。未批量删除 UI 基础组件或旧作品兼容路径；保留兼容行为比仅减少文件数量更重要。

## 自动调度
`autopilot.ts` 定义总 Agent 决策校验和文本动作白名单。添加动作必须同时增加前置条件、输出校验、下游失效规则及测试；不能把任意模型返回的函数名作为工具执行。`server.ts` 在副本上执行单步并备份、原子提交，`auto-run-driver.tsx` 常驻工作台、负责逐步推进；`auto-pilot.tsx` 提供预算、指令、停止入口与日志。工作台内切换页面不卸载驱动，关闭工作台则暂停后续推进。没有递归无限派单，也不暴露媒体生成权限。
