# LAMP 方法在工作台中的适配

参考：[项目页](https://cyberiada.github.io/LAMP/)、[论文](https://arxiv.org/abs/2512.03619)、[官方代码](https://github.com/mbkizil/LAMP)。

LAMP 将语言转换为主体与相机的符号运动程序，确定性求出共享世界坐标中的轨迹，再渲染指导视频用于视频模型的条件生成。官方实现使用训练后的规划模型和 VACE。

本项目采用这一设计思路，自行实现简化的 JSON 运动程序，不复刻官方 DSL，不声称使用 LAMP 权重或复现论文质量。当前支持一个主体的线性位移、世界坐标相机、相对跟拍和带方向的显式环绕角。平滑起停沿用镜头 easing。

- 入口：分镜编辑器 → 运动规划，可调用已配置语言模型或手动编辑。
- 持久化：Shot.motion，可选字段，老镜头继续使用原相机路径。
- 校验：有限坐标、角度范围、采样速度、相机距主体中心的距离。
- 预览：61 点采样，显示主体/相机俯视轨迹；不把坐标零点当作剧情轴线。
- 编译：同一运动程序进入媒体任务和 H3 提示词，提供起点、中点、终点及坐标语义。
- 控制边界：H3 当前适配使用文字运动指导和首帧，没有轨迹硬约束。自建网关接收 motionPlan 也不意味着它已实现轨迹条件生成。
- 缺失：多物体交互、骨骼动作、碰撞网格、VACE 指导视频渲染/条件推理、真实视频轨迹误差评测。当前距离检查只针对主体中心，不是完整碰撞检测。

跟拍/环绕模式下，旧 camera.start/end 表示相对主体的偏移。环绕角从 +Z 朝 +X 为正；终点使用 end 的半径及高度，方向由显式角度决定。因此起终点相同也可以表达完整 360 度绕行。

这些能力用于完善“动作指导 → 摄影规划 → 轨迹校验 → 用户调整 → 提示词编译”的链路。保存轨迹后按既有规则使下游素材和审查版本失效；不自动付费重生。
